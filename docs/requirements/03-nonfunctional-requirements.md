# RentManager 非機能要件

版: 0.1（レビュー用ドラフト） / 作成日: 2026-09-23

01-requirements.mdの決定事項・仮定を継承する。以下の数値や実装条件はレビュー対象の提案。全項目をMVPの検証条件とし、実装担当が確認結果を記録する。

| ID | 分類 | 要件・検証条件 |
|---|---|---|
| NFR-01 | 認証 | Neon Authで認証。未認証者はログイン画面と公開説明以外の社員・備品データを取得できない。ログアウト後のセッションは利用不可。セッションをlocalStorageに自作保存せず、SDKの推奨するサーバー検証方式を使用。Cookie方式では本番Secure・HttpOnly・適切なSameSiteを確認する |
| NFR-02 | 認可 | すべての保護リクエストで有効社員と権限を確認。入力されたroleや社員IDを信用しない。備品・社員管理は管理者のみ、返却・延長は本人または管理者のみ。無効化・降格後は既存セッションでも次のリクエストから制限する。UIを迂回した直接リクエストで検証する |
| NFR-03 | デモ認証の制限 | メール送信、公開セルフサインアップ、自己サービスの資格情報変更・削除を無効化。初期管理者は資格情報と権限を固定し、管理画面だけでなく認証APIからも変更できない。Neon Authの実構成で検証できるまで、この部分を実現済みと扱わない |
| NFR-04 | 機密・データ保護 | DB接続情報・Neon管理キー・認証秘密情報をサーバーの環境変数に置き、Git・Issue・ブラウザJS・ログへ出さない。公開する共通デモ資格情報は専用の低権限サービス資格情報とは区別し、他サービスと使い回さない。TLSで接続。実在個人情報を入力しない旨をログイン・社員追加画面に表示する |
| NFR-05 | 入力とリクエスト保護 | すべての更新をサーバー側でも検証し、SQLはパラメータ化する。氏名・説明等はHTMLとして解釈しない。Cookie認証の更新操作はCSRF/Origin検証を行う。外部サイトからの変更リクエストが拒否されることを確認する |
| NFR-06 | 整合性・競合 | 未返却貸出は備品につき最大1件となるDB制約を設ける。削除と貸出、返却と延長、同時延長、最後の管理者の同時変更はトランザクション等で整合性を保つ。返却再送は最初の記録を保持。2クライアント同時貸出等のテストで部分更新・重複・上書きを検証する |
| NFR-07 | 性能 | 基準データは備品20点・社員4人・履歴200件、同時利用10人。ウォーム状態の主要読み取り・更新を各20回計測し、サーバー処理時間の95パーセンタイル2秒以内を目標とする。無料環境の初回起動遅延は別記録。全取得・更新にローディング表示があり、15秒を超える待機では遅延案内または再試行案内を出す。更新再試行前に成功済みか再取得する |
| NFR-08 | 可用性・障害時 | 無料デモのため稼働率SLAは設けない。DB・認証停止時は日本語のエラーと再試行を表示し、成功を偽装しない。期限判定にバッチを要さない。公開URLでログイン→貸出→返却が一巡することを公開完了条件とする |
| NFR-09 | 対応環境 | 日本語。検証時点の安定版Chrome/Safari/EdgeをPCで、iOS Safari/Android Chromeをスマートフォンで対象とする。少なくとも幅375/768/1440pxで一覧・フォーム・モーダルが操作可能。ページ全体の横はみ出し、切れた主要ボタン、スマホで選択できない日付入力がないことを確認する。未実機検証の環境は未確認と報告 |
| NFR-10 | アクセシビリティ | 主要操作はキーボードのみで完了可能。入力ラベル・エラー関連付け・見えるフォーカス・適切な見出しを設ける。モーダルはフォーカス管理と閉じる操作を提供。状態は文字と色の両方で表示。通常文字はコントラスト4.5:1以上。主要操作のタップ領域は44px以上を目安とする。WCAG全項目への適合を未検証のまま宣言しない |
| NFR-11 | 復元・初期データ | 架空データのため操作履歴のバックアップ保持保証は対象外。マイグレーションとシードをGitで管理し、空の専用テストDBから初期デモを復元可能にする。既存公開デモの初期化では初期管理者を維持。実行対象チェック・明示フラグを必須にし、Web経由の初期化を作らない |
| NFR-12 | ログ | サーバーエラーに時刻・処理名・追跡IDを付け、必要時のみ対象の内部IDを記録。パスワード・Cookie・トークン・接続文字列・入力本文を記録しない。返却実行者・延長実行者は業務履歴に保存。閲覧者画面は追跡IDだけで問い合わせ可能。独自ログ基盤は追加せず、保持期間は選定先の無料プラン仕様を記録する |
| NFR-13 | 保守・検証 | TypeScriptを使用し型チェック・lint・本番buildが成功する。ロックファイルをコミット。READMEに起動・環境変数名・マイグレーション・シード・初期化・検証・公開手順を書く。最低限、権限違反・無効化・初期管理者保護・二重貸出・削除競合・返却再送・延長・日本時間境界の意味あるテストと、主要フローの公開環境確認を行う |
| NFR-14 | 費用・公開 | 有料契約・無料枠の自動有料化を行わない。Vercelの用途・プラン条件が合わない場合はCloudflare Workersを候補に、Next.js・Neon Auth・サーバー機能の互換性と無料枠を確認する。公開先を決定してからデプロイ設定を固定。サービス標準URLでよく、独自ドメインは不要。公開デモが第三者から閲覧可能か認証済みセッションを持たないブラウザでも検証する |
| NFR-15 | 開発と公開の分離 | 開発・自動テスト用DBと公開デモ用DBをNeonブランチ等で分離する。テスト・シードで公開デモを消さない。並列担当のマイグレーション管理を一本化し、認証設定・接続先・シークレットを環境別に管理する。公開先のドメインを認証の許可先に登録してログインを検証する |
| NFR-16 | 公開デモの資源制限 | 仮案として社員は最大20人、未削除備品は最大100点。サーバーで同時作成時も上限を守る。ログイン試行はIP単位で5分20回、書込操作は社員単位で1分60回を目安に共有ストアまたはプロバイダー側で制限し、超過時は待機案内。無料で利用可能な実装を選び、追加有料サービスは導入しない。一般公開でも悪用を完全には防げないデモであることを前提とする |
